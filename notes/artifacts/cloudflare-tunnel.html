Cloudflare Tunnel — what it is, and why the URL matters so much

Plain English: what a tunnel does, the difference between the free temporary one and a permanent one, and why that difference decides whether our released app keeps working.

The problem it solves

Our backend runs on a laptop. That laptop is the only machine that can reach the switches (it's on the VPN). But a phone out in the world cannot call a laptop — the laptop has no public address, and we are not going to open holes in the firewall.

A Cloudflare Tunnel fixes this. A small program (cloudflared) runs on the laptop and makes an outbound connection to Cloudflare. Cloudflare then gives us a public https:// address, and quietly forwards anything sent there down that connection to our laptop.

📱 Phone ──https──▶ ☁️ Cloudflare ──(tunnel)──▶ 💻 Laptop ──VPN──▶ 🔌 Switch

No open ports. No public IP. Free HTTPS certificate. That's the whole appeal.

Why this matters for a released app

The backend address is baked inside the app when we build it.

Once the app is installed on someone's phone, that address cannot be changed. So if the address changes, the installed app is pointing at somewhere that no longer exists — and it simply stops working.

With a quick tunnel, the address changes every single time it restarts. Which means:

  • Laptop sleeps, reboots, Wi-Fi drops, or the tunnel hiccups → new address.
  • Every installed app instantly breaks for every tester.
  • We must rebuild the app, upload a new build, and everyone must update.
Also: the laptop and the backend must stay running the whole time. If we shut them down, the app stops working for everyone — no matter which tunnel we use.

How to set up a permanent (named) tunnel

One-time setup, about 15 minutes. You need a domain (any domain, ~$10/year) added to a free Cloudflare account.

one-time setup
brew install cloudflared              # if not installed
cloudflared tunnel login              # opens browser, pick your domain
cloudflared tunnel create racktrack    # creates the tunnel + credentials
cloudflared tunnel route dns racktrack api.yourdomain.com

# then run it (this address never changes):
cloudflared tunnel run racktrack

From then on the backend is permanently at https://api.yourdomain.com. We build the app once against that address and it keeps working across restarts, reboots and rebuilds.

Bonus: you can also install it as a background service (cloudflared service install) so it starts automatically with the machine — no more "did someone forget to start the tunnel?"

Our plan

  1. Now — quick tunnel, for a first TestFlight build. Free and instant. Good enough to prove the whole app works on a real iPhone, end to end.
    Accept the catch: that build is disposable. The moment the tunnel restarts, the address changes and that build stops working. Do not hand it to real customers.
  2. Next — buy a domain and switch to a named tunnel. Then the address is permanent, the app keeps working, and we can distribute it properly.

A way to avoid the rebuild pain (worth considering)

We could add a small “Server address” setting inside the app, so the backend URL is read at run time instead of being baked in at build time. Then, when a temporary tunnel address changes, a tester can just paste the new address — no rebuild, no re-upload. It's a small change and it makes beta testing far less painful.

The short version

Do we have to use Cloudflare?No — any tunnel (ngrok, Tailscale) or a real host works. Cloudflare is just free and easy.
Why do we need a tunnel at all?Because the backend must stay on the laptop that can reach the switches.
Can we ship with the free quick tunnel?Only for a throwaway test. Its address changes and breaks every installed app.
What do we need for a real release?A domain (~$10/yr) + a named tunnel = one permanent address.

Bottom line: the tunnel is what lets a phone anywhere reach a laptop that can reach the switches. The free one is fine for proving it works. The moment other people rely on the app, we need a permanent address — otherwise a single restart breaks everyone.
