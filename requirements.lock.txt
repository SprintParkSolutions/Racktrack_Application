# requirements.lock.txt — pinned, reproducible Python dependency set.
#
# HOW THIS WAS GENERATED
#   The project ships a virtualenv at .venv/, but it is a *Windows* venv
#   (pyvenv.cfg -> Python 3.13 on C:\...) and cannot be executed on this
#   host, so `pip freeze` could not be run directly. Instead these exact
#   versions were read from the installed package metadata in
#   .venv/Lib/site-packages/*.dist-info — i.e. the same versions `pip freeze`
#   would emit for the packages that are actually installed there.
#
# CAVEATS (read before trusting this as a full lock):
#   1. The source .venv is the CV/ML working env and does NOT contain five of
#      the direct requirements: easyocr, openpyxl, msal, psycopg2-binary,
#      python-dotenv. Those are listed at the bottom at their requirements.txt
#      floor and should be re-pinned after a clean `pip install -r
#      requirements.txt && pip freeze` on the target (Linux/Python 3.11) image.
#   2. numpy in the .venv is 2.4.6, which VIOLATES the `numpy>=1.26,<2.0`
#      constraint in requirements.txt. Reconcile before shipping: either lift
#      the ceiling in requirements.txt or install numpy 1.26.x here.
#   3. requirements.txt asks for opencv-python-HEADLESS; the .venv has the GUI
#      build (opencv-python). The headless variant at the same version is
#      pinned below (correct for a server/Docker runtime with no display).
#
# USAGE (reproducible install on the runtime image):
#   pip install --extra-index-url https://download.pytorch.org/whl/cpu \
#       -r requirements.lock.txt
