What was audited, and how

Seven independent passes over the tracked source — server (18.5k lines), React client (28.8k), Python pipeline (12.5k), ServiceNow integration (5.7k) — each with a narrow brief: security, server correctness, React correctness, pipeline correctness, incomplete/dead code, performance, and finally an adversarial re-audit of the fixes themselves.

Every finding in this report was verified against the source before being reported, and the important ones were reproduced against a running server. Several plausible-sounding findings were discarded as false positives — noted below, because knowing what isn't wrong matters too.

The headline: scanning was completely broken

Every single-image scan failed with "Please upload a clearer photo of the rack." rackScope(_a) referenced a variable declared inside a bare block that had already closed, so POST /api/analyze threw ReferenceError on every request. The handler caught it and returned a 400 blaming the user's photo — so the failure looked like a camera problem, not a bug. Introduced hours earlier by commit 69e7047. Fixed and verified.

Correctness bugs fixed

  • Multi-rack video split had never worked — it read a config key (models.devices) that has never existed, failing with KeyError on every call.
  • A failed Python spawn hung every request forever — the worker pool logged the error but never rejected pending work or respawned, so the server looked healthy while scanning silently stopped.
  • Pipeline errors killed the warm worker — SystemExit bypassed the except Exception guard, taking down the process instead of failing one request.
  • Topology "← Back" always threw — goBack was declared in the parent component, not the one rendering the button.
  • Two blank-page crashes in Marketplace orders from spreading a null object.
  • Nine API calls sent no credentials — converted to the authenticated fetch wrapper.
  • Missing database indexes — the owner console full-scanned the audit log every 5 seconds.

Verified clean

Checked specifically, and genuinely not a problem — so no one wastes time on them:

  • No SQL injection. Every statement is parameterised; the only interpolations use hardcoded column allowlists.
  • No command injection. All subprocess calls use argument arrays, never a shell string.
  • No broken frontend↔backend links. All 137 client API calls resolve against the 214 registered routes — no 404s, no verb mismatches.
  • Rules of Hooks clean across every React component, including the 4,900-line results page.
  • JWT handling sound — no weak fallback secret.
  • A reported email-header injection was a false positive — the address regex rejects newlines.
  • Mock data-source routes are correctly disabled in production (verified live).

Assessment

The architecture is sound and the security primitives already existed — role checks, tenant ownership, report tokens, rate limiting. The failures were consistency failures: a guard applied to four routes and not the fifth, a check that returned true instead of false, a static mount added before the auth layer. That is a far better position than missing primitives, and it is why most fixes were a few lines each.

The two systemic gaps worth naming: almost no automated tests, so a one-line scoping regression broke the product's primary flow undetected; and multi-tenancy is enforced per-route rather than structurally, which is why isolation gaps keep appearing one endpoint at a time.
