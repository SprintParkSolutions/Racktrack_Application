The code · benchmark question raised by your lead

Coding standards the codebase is benchmarked against

A coding standard is an agreed rulebook for how code is written, plus tools that enforce it automatically so it never depends on memory. Professional teams state precisely which rulebook and which tools they use. Here is RackTrack's, verified against the actual repository configuration. The JavaScript stack is fully standardised today; the Python stack is the one material gap.

JavaScript: fully enforced Python: tests only
A note on "MISRA": that standard governs C / C++ in safety-critical embedded systems (automotive, medical). It does not apply to a Python + JavaScript web/mobile product. The correct benchmarks here are PEP 8 / PEP 257 (Python) and the ESLint-recommended + Prettier conventions (JavaScript/React).

The statements — ready to hand to your lead

JavaScript — app & server TRUE TODAY

Follows a consistent style enforced by EditorConfig (UTF-8, LF, 2-space indent) and Prettier (single quotes, semicolons, 100-column), statically linted by ESLint 9 (flat config — eslint:recommended + react + react-hooks, reconciled via eslint-config-prettier) under a CI-enforced warning ceiling. Tested with Vitest + Testing Library, node:test, and Playwright. Security via npm audit, gitleaks and Semgrep, gated by GitHub Actions on every push.

Python — AI pipeline TARGET — needs 4 tools

Should follow PEP 8 and PEP 257, with Ruff (format + lint), mypy (static typing), pytest (tests), and Bandit + pip-audit (security) — all enforced by CI gates. Today only pytest is true (101 tests, CI-gated).

Why If that disk dies, every scan and account is gone forever. The two-step save can also lose a scan on a crash.
