RackTrack Cloud Brief

What it takes to run RackTrack in the cloud, on one page. You'd be hosting one Docker image — React app, Express API (~203 endpoints), SQLite, and Python workers holding six CV models resident — behind Caddy for TLS. The demo at demo.racktrack.ai already runs this exact shape on a 2-vCPU/8 GB VPS; going to the cloud "for real" means a bigger box and a short hardening list, not a rewrite.

No GPU needed

The container is CPU-only by design: 3–8 s per rack scan on ordinary vCPUs. A GPU only pays off for heavy scan volume or model retraining — and retraining is better rented by the hour ($1–3 per run).

One box hosts everything

Rule from the repo itself: one inference worker per ~3 GB RAM, never more workers than cores. An 8 vCPU / 16–32 GB server (~€20–60/mo) carries ~25–75 active users with zero code changes.

Real scale needs surgery

SQLite, in-memory rate limits, local disk and background pollers all assume a single process. Past ~100 users: Postgres + Redis + object storage + a job queue, then replicas.

The plan for 100–10,000 users

Assuming field-ops usage (5–10% of users active in the peak hour, 2–6 scans each), the growth path is three phases — and the heavy engineering sits in the middle one, best done before the users arrive:

PhaseCarriesInfraMonthlyWork involved
A — bigger box100–300 users8 vCPU / 32 GB, OCR capped, volumes + backups fixed$40–80days — config and hardening only
B — the platform migration300–1,500API box + inference box, Postgres + Redis, object storage, job queue$200–4003–6 weeks — SQLite→Postgres, queues, storage; the one big project
C — replicas + GPU1,500–10,0002–3 stateless API replicas + LB, one GPU inference node, OCR on GPU, CDN$800–2,0002–4 weeks — mostly infra; OCR GPU unpin is code

The GPU verdict flips inside this range: past ~1,000–2,000 scans/hour (≈3,000–5,000 users), one rented GPU node beats 3–4 CPU boxes on price and is the only real cure for the 1–2 minute OCR lag. At the top of the range, storage runs 0.4–1.6 TB/month of scan artifacts unless the PNG→JPEG fix lands first, and the apps need real Play Store / App Store releases pointed at a permanent api. domain.

Fix before real customers

  • Database not on a volumeThe base compose leaves auth.db + JWT secret in the container layer — one rebuild without the mount erases every account. One compose edit + nightly backups.
  • Secrets in the repoA plaintext ngrok token, tester passwords, and Microsoft token caches live in the tree. Purge and rotate before any shared host.
  • A model file exists only on the serverport_count.pt is missing from the checkout; a fresh deploy fails mid-scan. Version all six weights in object storage.
  • OCR has no limitsEach background OCR grabs every core for 1–2 min, uncapped — the throughput ceiling and the burst-crash risk. Cap it at 1–2 concurrent.
  • Disk grows foreverNo retention on scan outputs; PNGs dominate. JPEG the stage images and add a cleanup policy.
