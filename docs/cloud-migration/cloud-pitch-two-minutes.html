The RackTrack Cloud Pitch

Scroll through the six slides. Under each one, the green box is literally what you say out loud.

Slide 1 · Where we are

Everything runs on one small server

Website, AI, user accounts, photos — all on a single rented machine. If it fails, everything stops. It's fine for a demo, not for real customers.

You say

"Today the whole app runs on one small server. It works, but one machine is one point of failure — that's what we're fixing."

Slide 2 · The good news

Our app is already cloud-ready

The app is packed in a standard container (Docker) and already runs on a rented cloud machine today. Moving it is not a rebuild — it's a proper upgrade of where and how it runs.

You say

"Good news: I checked the whole codebase. The app is already packaged the standard way clouds expect, so this is a move, not a rewrite."

Slide 3 · Azure or AWS

Both are safe. AWS fits us better.

Both pass every standard — same security certificates, both have proper datacenters in India for our users' data.

AWS: its Mumbai datacenter has everything we need in one place, and this exact kind of move is best-documented on AWS.

Azure: connects naturally with the Microsoft tools our app already uses (Teams, Outlook) — and Microsoft offers startup credits that could make year one free.

You say

"On standards, Azure and AWS are equal — same certifications, both with datacenters in India. I recommend AWS Mumbai because everything we need is in one place there. But first I'll apply to both free-credit programs — if Microsoft gives us big credits, we take Azure. Same plan either way."

Slide 4 · The plan

Three steps, smallest risk first

1 · MoveCopy the app as-is to a proper cloud server. Add automatic backups and secure passwords.
2 weeks.
2 · Upgrade the insidesProfessional database, photo storage, and a queue for heavy jobs — so the app can run on many machines.
About a month of focused work.
3 · GrowRun 2–3 copies of the app plus an AI chip — only when user numbers demand it.
Later, triggered by usage.
You say

"Three steps. Step one, move it as-is — two weeks. Step two, upgrade the internals so it can run on many machines — about a month, and I need a feature freeze during it. Step three, add capacity as users grow."

Slide 5 · The cost

Starts small, grows slower than users

About $170/month at launch → about $1,400/month at 10,000 users.

Users grow 100×, cost grows only 8×.

You say

"Cost starts around 170 dollars a month and reaches about 1,400 at ten thousand users — users grow a hundred times, cost only eight times."

Slide 6 · The ask

I need three approvals

1. Provider choice — confirmed one week from now, after the free-credit answers.

2. Budget — the $170 → $1,400/month envelope.

3. One protected month — for step two, with a feature freeze.

You say

"From you I need three things: the provider decision next week once credits are answered, the budget envelope, and one protected month for step two. Then we're fully, properly in the cloud."

The whole pitch in five sentences

"Our app already runs in a container on a cloud server, so this is a move, not a rewrite.

Azure and AWS both pass every standard — I recommend AWS Mumbai, unless Microsoft's startup credits make Azure free for year one.

The plan is three steps: move as-is in two weeks, upgrade the internals in one focused month, then scale when users demand it.

Cost starts at about $170 a month and reaches $1,400 at ten thousand users.

I need the provider decision next week, that budget envelope, and one protected month."
