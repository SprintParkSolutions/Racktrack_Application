RackTrack, end‑to‑end.

A datacenter rack-scanning platform: point a phone at a rack, and a computer-vision pipeline maps every device, port, cable and label — organized under a three-tier Owner → Organization → Site model so each team sees only its own racks. This page walks the whole thing top to bottom.

3 account tiers 6 ML models ~3s per rack analysis React · Node · Python CV iOS / Android / Web

The organization model

A strict hierarchy. Each level owns the one below it; access flows downward.

OW
Owner
Platform level — oversees every organization
exactly 1
OR
Organization
A customer company. Created by the owner, each gets one Org Admin.
1 → many
ST
Site
A physical location / datacenter. Created by the org admin.
1 → many
MB
Members
The techs who scan racks. Added to a Site by their admin.
1 → many

Internally a Site is the “tenant” — the unit scans are scoped to. Scans (a claimed rack) belong to a Site; a Site belongs to an Organization; an Organization is overseen by the Owner. Active-learning corrections are shared at the organization level, so every site in a company benefits from each other's feedback while staying isolated from other companies.

04

Sign-in & routing

One smart form. The role toggle only decides which fields you need — the server proves who you actually are.

The form

Role toggle → fields

Member / Admin enter Organization + username + password. Owner enters just username + password. Picking a role can't grant it — a member who picks “Owner” still logs in as a member.

The proof

Verified server-side

Credentials are checked with bcrypt; a signed JWT carries the real role, organization and site. After login the app routes by the real role — owner & admin to the dashboard, members to the scanner.

Onboarding

Members are added

Admins create members (with a site) from the console. New companies self-register to start a fresh organization.

Security

Hardened

Helmet headers, login rate-limiting, JWT sessions, and secrets kept out of source control.

Recovery

Email codes

Email verification and password reset run on 6-digit codes with short expiry.

06

The AI/ML pipeline

Six stages, run by a warm pool of Python workers that keep every model resident in memory.

01

Capture & stitch

The rack photo is normalized; multi-frame captures of tall racks are stitched into a single aligned image.

OpenCVmulti-rack stitch
02

Device detection

A YOLOv8 segmentation model finds every device — 12 classes (switch, patch panel, firewall, router, gateway, server, PDU, PSU, UPS…). Boxes are de-overlapped and mapped to rack U-slots.

devices_seg.ptYOLOv8-seg12 classes
03

Port detection & status

For each port-bearing device a typed-port model classifies every port (RJ45, SFP, QSFP, console, USB…), while a status model marks each connected or empty. Patch panels are reconstructed to their full 24- or 48-port grid; PDUs use a dedicated outlet model.

04

Cable classification

An EfficientNet-B0 classifier reads the cable type and colour on every connected port (14 classes).

05

Text & labels

OCR lifts device labels and nameplates for identification and cross-referencing.

07

Access control

A single rule governs every scan, result, image and port endpoint.

Owner

Everything

Every rack on the platform — results, images, ports, reports.

Org Admin

Their org

Every rack owned by any Site in their organization; nothing from other orgs.

Member

Their site

Only racks their own Site has scanned.

Enforced centrally by one canAccessRack check wired into the rack guard and every read/select/feedback route — so visibility can't drift endpoint to endpoint. Dashboard “recent scans” are click-through: an owner or admin opens any scan they're allowed to see.

Owner dashboard

Whole platform

Organizations · sites · users · total scans, a per-organization breakdown, and recent scans across everyone.

Org-admin dashboard

Their organization

Sites · users · scans · active users, a per-site breakdown (users, scans, last activity), and recent scans in the org.

08

Architecture

Three layers plus the integrations that connect scans to the wider network of record.

Client

React + Capacitor

React 18 · Vite · React Router · CSS Modules. One codebase shipped as native iOS/Android and web — white-focused UI throughout.

Server

Node / Express

SQLite (better-sqlite3) · JWT + bcrypt · Helmet · rate-limiting · structured pino logging + Prometheus metrics + health checks.

Pipeline

Python CV

Ultralytics YOLO · EfficientNet (PyTorch) · EasyOCR · OpenCV, run as a persistent, model-resident worker pool.

Integrations

Network of record

Netdisco cross-checks scans against live LLDP/MAC truth · ServiceNow raises tickets from findings · an SSH poller watches switches for physical port drift.

Delivery

Containerized

Multi-stage Docker image (Node + Python) with compose, plus a GitHub Actions CI that lints, builds and smoke-tests.
