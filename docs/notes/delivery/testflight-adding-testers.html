Adding testers to TestFlight

For whoever holds the App Store Connect account. This covers getting a new person from “we should show them the app” to RackTrack running on their iPhone — and the one step that trips everyone up.

The thing that trips everyone up. An internal tester is not just an email address. You must first invite the person into App Store Connect as a user, they must accept that invite, and only then can you add them to the internal tester group. Two separate invitations, two separate emails. Skip step one and their name simply won't appear in the tester list.

Which kind of tester

Pick before you start — it changes the steps, the wait, and what you need from the person.

 InternalExternal
Who it's for Your own team — SprintPark staff, anyone with an App Store Connect seat Customers, prospects, pilot sites — anyone outside the account
Cap 100 people 10,000 people
Apple review? No — build lands as soon as it finishes processing Yes — Beta App Review on the first build of each version
Setup per person App Store Connect user invite, then tester group Email address into the group. That's it.
Time to hands-on Minutes Hours to ~2 days on the first build, minutes after

Default to internal. RackTrack's tester group is already set up as internal, which is why builds reach the team without waiting on Apple. Only reach for external when you're past 100 people or inviting someone you can't give an App Store Connect seat.

Internal — part one: the App Store Connect seat

Do this once per person. What you need from them: the email address their Apple ID uses. Not a work alias that forwards somewhere — the actual Apple ID. If they don't have one, they'll be walked through creating it when they accept.

appstoreconnect.apple.com → Users and Access → People → +
  1. Fill in first name, last name, email

    The email is the part that matters. Getting it wrong means the invite lands in a mailbox that can't accept it.

  2. Choose a role

    Developer or Marketing both work and are the usual pick for someone who's only there to test. Use App Manager only if they also need to manage the listing or upload builds. Avoid Admin unless you mean it.

  3. Leave “Access to Certificates, Identifiers & Profiles” unchecked

    Testers don't need it, and it's the checkbox that lets someone revoke your signing certificates by accident.

  4. Under Apps, grant access to RackTrack

    If you restrict a user to specific apps, RackTrack must be one of them or they won't see the build.

  5. Send the invite

    They get an email from Apple. They must accept it before part two will work. The invite expires — if it goes stale, delete the pending user and re-send.

Internal — part two: the tester group

Once they've accepted and show up as an active user, they become selectable as a tester.

App Store Connect → Apps → RackTrack → TestFlight → Internal Testing → your group → Testers +
  1. Tick their name in the list, then Add

    The list only contains App Store Connect users who have accepted. Missing name? They haven't accepted — go back to part one.

  2. Apple emails them a TestFlight invitation

    That's the second email, and it's the one the tester guide walks them through. Send them that guide alongside it.

  3. Confirm the group has a build attached

    An empty group invites people to install nothing. If the group shows no build, add the latest one to it.

External testers

No App Store Connect seat, no acceptance step — but Apple reviews the build.

TestFlight → External Testing → + to create a group → add testers by email
  • Add people by email address directly, or paste a CSV for a batch.
  • Attach a build to the group. The first build of each new version goes to Beta App Review — typically under a day, sometimes a couple. Later builds of that same version skip it.
  • A public link lets anyone install without you collecting emails first. Convenient, and worth thinking twice about — RackTrack points at your infrastructure, and a public link is a link anyone can forward.

Shipping a build to whoever's already in the group

Adding testers is a one-time act. Getting them a new version is a different loop, and it's already automated.

  1. Build and upload

    On the Mac: ./make-ipa.sh then ./ship-ipa.sh with the release notes as its argument. The notes become the “What to Test” text testers read in TestFlight — see client/ship-ipa.sh.

  2. Wait for Apple to process it

    Usually 5–30 minutes. You get an email when it clears. Until then it shows as processing and no one can install it.

  3. Answer the export compliance prompt if it appears

    RackTrack uses standard HTTPS only — nothing exotic. Already answered for existing versions; a new version number can ask again.

  4. Internal testers get it automatically

    No review, no action from you. Their TestFlight shows an Update button. External groups need the build attached to the group, and the review on a first build.

Limits worth knowing before someone hits them

LimitValueWhat happens at the edge
Internal testers100Add the 101st and you can't — prune, or move them to external.
External testers10,000Not a limit you'll meet.
Devices per internal tester30Per person, across their own iPhones and iPads.
Build lifespan90 daysThe build expires and testers are locked out until you ship a new one.

The 90-day clock is real. A build that testers were happily using will stop opening with no warning from anyone. If RackTrack is in someone's hands long-term, ship a fresh build before the old one lapses — even if nothing changed.

When it doesn't work

SymptomCauseFix
Their name isn't in the tester picker They never accepted the App Store Connect user invite Users and Access → check for Pending → re-send
They got the invite but TestFlight says nothing to install No build attached to the group Add the latest build to the group
“This beta isn't accepting new testers” Internal group at 100, or build expired Remove inactive testers, or upload a fresh build
Invite went to the wrong mailbox Work alias used instead of the Apple ID email Remove the user, re-invite with the real Apple ID address
App installs, then every screen fails Backend unreachable — not a TestFlight problem Check the Windows server and the tunnel URL baked into the build
